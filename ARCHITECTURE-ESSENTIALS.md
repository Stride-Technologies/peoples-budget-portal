# Architecture Essentials

The non-obvious rules that are easy to break. Each one cost a real bug or a
wrong answer before it was written down. Read this before changing code;
`CLAUDE.md` loads it into every agent session.

> **About `specs/NNN`.** Comments and docs cite feature specs (`specs/012`, `specs/017`) from the portal's
> first deployment, in Naga City. Those specs are not in this repository; the rule beside the citation is what matters.
> Figures and dates in the examples below are from that deployment too.

System shape is in [`ARCHITECTURE.md`](ARCHITECTURE.md); the public-page design rules
(no chart library, colour, snap, motion, `bg-paper`) are in [`DESIGN.md`](DESIGN.md);
domain invariants numbered 1–20 are in [`api/docs/aip-reference.md`](api/docs/aip-reference.md) §6.

> **Terminology.** "Publish model" = how programs work today (DRAFT → PUBLISHED ⇄
> PUBLISHED_REVISION). "Approval workflow" = the archived submit → head review → LFC
> chain on `archive/full-approval-workflow`, to be replaced rather than restored. Older
> docs call these "Phase 1" and "Phase 2"; contract phases P1–P4 in `PLAN.md` are a
> different thing.

## Data and money

- **Tables are snake_case; Prisma models are PascalCase.** `relation "Program" does not exist` means you guessed the table name — never write raw SQL from model names; check `schema.prisma` `@@map`s or introspect first.

- **`proposedBudget` is the public-view money field.** Public AIP amounts, page and overall grand totals, budget summaries, and drawers all derive from it. **On the public site it is labeled "Estimated Cost" in the AIP section and "Appropriation" in the Annual section (`AMOUNT_LABEL`), never "Proposed Budget"**: the AIP is a wishlist of planned programs, the proposed budget is the LEP the Mayor submits, and only the ordinance appropriates — the field name is historical. But a *program's* figure is **`Program.proposedTotal`**, read never re-derived: a `DIRECT_COSTS` program holds **no PAs at all** and states its cost on the program row, so summing root PAs reads ₱0 for it — 396 of the 492 published 2027 programs and ₱2.54B of ₱6.07B. For a program that does have PAs, `proposedTotal` already equals their sum to the centavo, so it is never double-counted and there is no case where the root-PA sum is the better number. This bit four call sites at once (the public registry aggregate, the drawer, the detail view, the list) and made the home hero say ₱3.53B where the staff registry said ₱6.07B. `totalBudget` and `totalProposedBudget` on the public registry response are deliberately the same figure. **Fund attribution has the same trap:** the funding entries are leaf PPAs *plus every program with no PPAs* (its own `fundSources` / `fundAllocations`); the staff dashboard's fund breakdown read PPAs only and showed ₱5.95B of ₱9.01B until 2026-10-15.

- **"Live" is `LIVE_PROGRAM`, not `deletedAt: null`.** An ARCHIVED program (specs/013) keeps its row, its `publishedVersionId` and its PAs. It is a superseded program kept for its history, and it must count nowhere. So a query that filters only `deletedAt: null`, or only `publishedVersionId != null`, silently puts its money back into a total. Staff lists, totals, exports, LBP forms, ceilings and code scopes use `LIVE_PROGRAM`, and anything public uses `PUBLICLY_VISIBLE`, both from `api/src/programs/program-filters.ts`. `PUBLICLY_READABLE` is only for the archived program's own link. The new status is safe in the other direction for free: every editability or publish guard is an allow-list of statuses, so ARCHIVED is refused without touching them. Two allow-lists had to *add* it: `ADOPTABLE_PROGRAM_STATUSES` (or the cycle could never be adopted), and the comment write guard, which read no status at all.

- **Never use `OR: []` to mean "match nothing".** Prisma reads an empty `OR` as false at the top level but as **true** once it sits inside an `AND` — and the registry composes visibility as `AND: [visibility, …filters]`. A user with no scope got `OR: []` from `buildVisibilityWhere` and listed every program (#102). Write `id: { in: [] }`, which is false in both positions; `OR: undefined` is worse still (it drops the condition).

- **A program's `papSectorId` comes from its office's configured sector when seeding** — not from a spreadsheet's AIP code prefix, which disagrees with the office catalog in places.

- **Discarding a revision rebuilds the PA subtree, and the rebuild cascades.** `restoreFromSnapshot` deletes every PA, which takes their `FundAllocation` and `ClimateChangeTag` rows with it, so each must be recreated from the snapshot — as must the program's own cost columns (`costMode`, `fundSources`, PS/MOOE/FE/CO), split and tag, which are the *input* on a `DIRECT_COSTS` program. A column or relation added to the snapshot and not to the restore comes back as the draft's value, or not at all.

## AIP codes and import warnings

- **Tentative AIP codes are derived, never issued.** `tentativeAipReferenceCode` is a stored column, but it is *derived state*: the ordinal is the row's rank among live siblings, not a counter value. Programs rank by **`papClass` first** (GAS → STO → Operations, nulls last), then `orderIndex` — the same order `AIPRegistryService.list` renders in, and the two must not drift or the codes print out of sequence. **The ordinal restarts inside each `papClass`**, so a null-papClass program shares the Operations bucket (both emit `003`, and numbering them separately would hand each `001`). Never write it directly — call `AIPCodesService.resyncTentativeProgramCodes` / `resyncTentativePACodes` inside the same transaction as your mutation. Anything that changes a segment (office, PAP sector, papClass, office code/type) or the population/order (create, delete, reorder) must resync — `papSubsectorCode` is **not** a segment any more and no longer triggers one. `AIPCodeCounter` now serves the **final** code only. Full rules: `api/docs/aip-reference.md` §7 and invariants 15–18. Two offices sharing both `officeCode` and `officeType` will derive the *same* code and collide on the unique index — `prisma/data/offices.check.ts` pins the intentional cases.

- **A warning is stored only if it cannot be re-derived.** `Program.importWarnings` holds *only* the decisions an import had to make on a row's behalf — the 2027 workbook's inferred finish line, duplicate merge and synthesised heading, and AB 2026's uncoded row, duplicated code and blank description — each leaves the row looking identical to one authored on purpose, so nothing can re-check it, and only `POST /programs/:id/acknowledge-import` clears it. **Being unre-derivable is necessary but not sufficient: the warning must also be about *that row*.** AB 2026's inferred finish line met the first test and failed the second — the book states a finish line nowhere, so all 430 programs carried the identical sentence, and it gated the whole enacted budget while distinguishing nothing inside it. It is now reported once, by the seed and the import report. Dropping it took 2026 from 0 publishable to 383, with the 47 genuinely row-specific ones still gated. Every other warning is derived per read by `api/src/programs/import-data-warnings.ts` and returned as advisory `warnings`. Breaking this caused a real bug: storing data gaps meant the sentence outlived the fix and 145 of 225 seeded programs were unpublishable no matter what their office corrected. If you add a check, derive it — reach for storage only when you can prove the condition vanishes from the data. Full rules: `api/docs/aip-reference.md` invariant 20 and `docs/design/import-warnings-revalidation.md`.

## Budget rules

- **A special fund is a fund source, not an office.** LDF (20%), SPA and LDRRMF rows sit under their implementing office and carry the special fund beside the row's own fund (`[TRUST_FUND, LDF]`, `[GF, SPA]`). Never create an office for a fund. Each fund's legal basis and legal minimum is a `FundRule` row (a floor: the laws say "not less than"); rule checks are derived, never stored. On the public site a special fund is a badge, a Browse filter and `/annual/<fy>/funds/<fund>`, never an office band.

- **The public headline total sums `publishedProposedTotal`, never the live `proposedTotal`.** A program in PUBLISHED_REVISION is public at its published figure; summing the live column leaked its unpublished draft into the total while its row showed the old figure.

- **Climate tags sit on a PPA or a program and carry 0..n CCET codes.** `ClimateChangeTag` has exactly one of `projectActivityId`/`programId` (a DB CHECK) and its codes in `climate_change_tag_codes`. The catalog is the **local** CCET typology from the CCC LGU training manual (`docs/design/ccet-typology-local.md`) — not the national manual, whose codes overlap but differ. A tag with an amount and no code is allowed (the city's AIP has them) but is an `INCOMPLETE_DATA` blocker, derived, so adding the code clears it; CCA+CCM is checked against the row's proposed budget, not line items, which imported rows do not have.

- **The expense classes are PS, MOOE, FE, CO — everywhere, in that order.** FE (Financial Expenses) was added by specs/008 beside every MOOE column, default 0. A list of classes that names MOOE and not FE is a bug: the rollups, DTOs, exports, dashboard, public payloads and open data all carry it. Two rules came with it: **public and open-data FE reads the snapshot only** (no live fallback, unlike PS/MOOE/CO), so a pre-FE snapshot reads 0 and a draft FE never leaks; and **FE shows on public pages only when non-zero**, so 2026 looks exactly as printed.

- **A special fund's stated amount is staff-only.** `FundStatedAmount` (SPA, LDF, LDRRMF, one per fund and cycle) is what the General Fund's LBP Form 7 prints when no row carries the fund; when rows do, their sum wins — whichever office they sit under. It appears on Form 7, the staff dashboard, the registry and the cycle page — never in a public total or open data. Don't add it to any public aggregate.

- **An office's header has a year: store it per document, never on the office (specs/017).** `Office.mandateLegalBasis` / `vision` / `mission` / `organizationalOutcomes` are the office's *current* header, maintained by staff and printed on the AIP's LBP Form 4 and the Word Annual Budget. Each book's own header goes to `BudgetOfficeHeader` (document × office). The document seed used to write every year's header onto the office, so loading FY2023 after FY2026 replaced the current text with older OCR ("Enactordinancesandapprove…"), and on scanned sheets the old preamble reader had taken the page's "Naga City" subtitle for most mandates. Headers are now read with positions (`lib/ocr-header.py`), and `seed-budget-document.ts --headers --book <json>` writes them onto an existing document.

- **A budget book's receipts and printed totals are never summed into the budget (specs/017).** `BudgetReceiptLine` is the money coming in. An enterprise's own receipts sheet restates part of the General Fund's program, so adding the two double-counts it. `BudgetPrintedTotal` exists only to check derived sums against. Book account codes resolve to `ChartAccount` (COA's LGU chart). `UACSObject` is still the AIP's own expense-object list: don't merge the two.

- **LBP Forms 4 and 7 read money on leaves only, through `lbp-figures.ts`.** One normaliser serves live rows and published snapshots, one fund-attribution rule (no fund → General Fund, listed; unsplit multi-fund → left out, listed), and `office-sheet.ts` is shared with the Word Annual Budget so the two cannot drift. A PPA parent prints no amount — the old Word export printed the parent's rolled-up figure *and* its children's and double-counted every nested 2027 program. Summed over every fund, Form 4 plus the listed multi-fund rows equals the cycle total to the centavo; check that after touching either file.

- **A row's money can be split by fund, and then the split is the money.** `FundAllocation` (one line per fund, PS/MOOE/FE/CO each, on a `DIRECT_COSTS` PA or program) is optional; without it a row is one total over its `fundSources`, exactly as before. With it, `EstimateRollupService` writes the row's PS/MOOE/FE/CO and `fundSources` from the lines, so never write those directly on a split row — go through `replaceFundAllocations` then the rollup. Attribution (public overview, staff dashboard, Fund Source sheet) reads the lines; only an *unsplit* multi-fund row goes to the multiple-funds bucket. Exports print a split row one line per fund. **`SHF` is the Special Health Fund** (the health offices' fund), not Socialized Housing. See `api/docs/aip-reference.md` invariant 21.

- **Every imported row cites where it came from: file, page, and place in the file.** A row points at a `SourceDocument` (the city's file, by name; `url` when it is hosted) with `sourceDocumentId`, keeps `sourcePage` when the file has pages (a PDF, an OCR import; a Word `.doc` stores no pagination, so FY2026 has none), and `sourceRef` for the table/sheet and row (`table 78 row 12`, `BCS-2026!r11`, `ECON!r305`). `common/source-link.ts` turns that into one link for staff. A new importer records all three; a carried-forward row cites its source row's file and cell. AIP Programs/PAs carry file + `Sheet!rN` today.

## Public site routing

- **Public routes are three sections plus a table.** `/aip/[year]/{overview,browse,methodology}` is the proposal, `/annual/[year]/{...}` is the enacted budget, and which one(s) a year belongs to is **computed by the API** — `computeSections` in `api/src/budget-cycles/cycle-sections.ts`, returned as `sections` on `GET /public/cycles` — and the client only reads it (`client/src/lib/public-sections.ts`). Never re-derive it from `status`: adopting an AIP (`ADOPTED`, formerly `LOCKED`) does not make a year an Annual Budget, an enacted Ordinance does (specs/012) — or, for a historical year with none, its SUBMITTED LEP (specs/017: FY2023–25 are posted only as the Mayor's proposal; one predicate, `PUBLIC_ANNUAL_DOCUMENT` in `public/ordinance-registry.ts`, decides it for every public read, and the client labels it "Proposed Budget" with an LEP tag and no Overview) — and until FY2026's Ordinance is enacted an interim clause keeps the historical 2026 record in Annual only — and only while the year has a public program, because a year imported from scans gets an *empty* adopted AIP cycle (the public site keys years on it) and must show nothing until its Ordinance is enacted. A year 404s in a section it is not in, and a year can be in **both**: once an AIP year's Ordinance is enacted, `/aip/<fy>` stays live with a link to `/annual/<fy>` and back (`SectionChrome`). Every registry/finish-line fetch passes the page's `section`, because with both documents present the API needs to know which one the page means. `/ppmp/[year]/{...}` is the third section and offers **every** year, whatever its status (`PublicSection` = `SectionKind | 'ppmp'`; `SectionKind` stays budget-only). **Each section's Overview is a per-year switch** (`AIPCycle.public{Aip,Annual,Ppmp}OverviewEnabled`, defaults off / on / off): off, `tabsFor` drops the tab and `loadSectionCycle(kind, year, 'overview')` redirects to Browse — so always pass the page's tab to `loadSectionCycle`, and link with `sectionHref` rather than hard-coding `/overview`. **Methodology is hidden site-wide while `METHODOLOGY_PUBLIC` is false** (`lib/public-sections.ts`): `tabsFor` drops it, `loadSectionCycle` redirects any tab the year does not show to Browse, and the hand-off and outline links check the same flag. `/ppmp/[year]` is also where old `/ppmp/<uuid>` plan links land (one dynamic segment per level), and it redirects them to `/ppmp/<fy>/plan/<id>`. `/budget` still exists and is unchanged, but is **not in the nav**: it is the parent of `/budget/[programId]/[paId]` and where `/registry` and pre-rename `/aip/<programId>` links land. That last redirect is narrowed to **uuid-shaped** segments in `client/next.config.ts` — Next matches redirects *before* routing, so a broad `/aip/:path*` shadows every page under `/aip/<year>/` and the section becomes unreachable. **The middleware protects a list of staff prefixes, not a list of public ones** (`client/src/lib/protected-routes.ts`). It used to be the other way round: a new public route had to be added to `PUBLIC_PREFIXES` or logged-out visitors were sent to `/login` (it bit three times), and every unknown URL answered a 307 to `/login` that Google indexed. Now a new public route needs nothing, an unknown URL is a 404, and a new top-level **staff** route must be added to the list — `protected-routes.test.ts` fails until it is — this has now bitten three times. **A visitor and a logged-in user see different nav components**: `(public)/layout.tsx` renders `PublicNav` for anonymous visitors and defers to the root layout's `Navbar` for everyone else, so a nav label or href has to change in *both* files plus the footer's "The Portal" list, and the one the public sees is `public-nav.tsx`.

- **A language is a URL prefix the middleware strips, so anything that builds a URL must put it back.** `/bcl/learn` is rewritten to `/learn` with an `x-locale` header *after* the protected-route check runs on the stripped path, so `/bcl/aip-registry` is still the staff app (and is redirected to `/aip-registry`). Inside a page the prefix is gone: a plain `next/link` or `redirect()` sends the visitor back to English — `/fil/ppmp/2027/overview`, with its Overview off, redirected to English Browse until `localeRedirect` existed. Use `LocaleLink` and `localeRedirect`. A translation is shown only while its `src` equals today's English, so editing `en.json` silently reverts that string to English until `pnpm translate` and a reviewer catch up — that is the design, not a bug. Budget terms and data are never translated (`client/src/i18n/`, `docs/architecture/frontend.md` → Languages).

- **A page that sets its own `openGraph` must include `images: OG_IMAGES`** (`client/src/lib/seo.ts`). Next merges metadata shallowly, so a page's `openGraph` replaces the layout's whole object — and a file-based `opengraph-image` is dropped the same way (tried). Thirteen public pages shipped with no share image because of this.

## Open data

- **Open data copies named fields only — never spread a snapshot.** A `ProgramVersion.snapshot` is the raw Prisma row with its whole tree, so it carries `createdByUserId`, `publishedByUserId`, `sourceRef`, `sourceDocumentId`, `remarks` and line items; the public detail strips some of these by hand (`stripProvenance`), which works only until someone adds a column. `api/src/open-data/open-data.mapper.ts` builds every row from column definitions, and `open-data.mapper.spec.ts` fails on any key outside them or any salted personal value in the CSV or JSON. A new field is exposed by adding it to those column definitions — which also adds it to the `METADATA.md` dictionary — never by spreading. A year is served only while `AIPCycle.openDataEnabled` is on; closed and unknown years answer the identical 404. `Program.publishedAt` is the **first** publish only: the time a version went public is `ProgramVersion.submittedAt`. See `docs/modules/open-data.md`.

## Data Explorer

- **A deterministic rule on a model's answer must also run on the cached answer.** Ask caches the validated view for 30 days, keyed by question, catalogue and prompt version, not by code. A clean-up added later (`withoutTopicOverlap`) never reached questions answered before it: on dev a cached "youth" view stayed empty after the fix. Rules that only remove or rewrite filters run on both paths (`ask.service.ts`); a change that alters *what the model is asked* bumps `EXPLORER_PROMPT_VERSION` instead. The reverse holds too: an answer made while the embedding index is unreachable is **not** cached (`ResolveService.lookup` → `degraded`), or a hint-less view outlives the outage by 30 days (dev, 2026-11-10: the VM had no model role and "20% development fund" lost its fund filter).

- **The workspace's charts run Vega through `vega-interpreter`, and must keep doing so.** Production's CSP has no `unsafe-eval`, and Vega compiles every expression (axis labels, tooltips, the treemap's text) with `Function` by default: the chart throws in production and works under `next dev`, which allows eval. `vega-chart.tsx` parses with `{ ast: true }` and runs `expressionInterpreter`. Check a chart change against `next build && next start`, not the dev server.

- **The chat never writes a figure; labels never add up.** The chat's model returns a query and sentence templates with placeholders; `chat.ts fill` puts the engine's figures in and drops any sentence with a digit of the model's own (years asked about excepted). Add a fact by adding a placeholder, never by letting the model compute. Labels (`label`, `subLabel`) are multi-valued like themes: no total across them, and a program keeps its own labels before its children's, or one drainage activity counts a whole office program as infrastructure money. A label in review counts nowhere, and a row Stride reviewed is never relabelled (`explorer_rows.reviewed_at`). The records cache is keyed by catalogue version, which carries a labelling stamp: a relabelled row shows without a cache flush.

- **Write vectors with raw SQL, never a Prisma `upsert`.** Prisma 7 kept about 215 KB of heap for every upserted 1,536-number embedding, even after GC (483 MB at 2,048 rows, against a flat 42 MB for `$executeRaw … on conflict`), and the first dev labelling run died at Node's 2 GB limit 7,000 rows in. `label-rows.ts` writes `explorer_rows` with raw SQL; anything else that stores embeddings must do the same. Its `updated_at` is written `now() at time zone 'utc'`, because the column is a plain timestamp and Prisma keeps UTC.

- **A barangay is read from a row's name every time, never stored (specs/020 A3).** `withBarangay` runs in `QueryService.records` *after* the record cache, because records are cached by catalogue version and a code deploy does not change that version: a barangay put on records inside the loaders would have been missing from every cached record until it expired. It is multi-valued (a "Sabang-Igualdad" road counts in both), so no total across barangays, and `perCapita` divides by PSA 2020 population, never by a guessed one. Building it found an older bug: the engine accumulated a field once *per measure*, so `[sum, avg]` of the amount doubled both; `add()` now reads each field once.

- **A record's shape is part of its cache key (`RECORDS_SHAPE` in `query.service.ts`).** Explorer records are cached per catalogue version, and a code deploy does not change that version, so a field added to a loader's records (specs/020: `parentId` on activities) would be missing from every cached record until it expired. Bump `RECORDS_SHAPE` with any change to what a loader puts on a record. Fields derived from a record (barangay, words) are attached after the cache instead and need no bump.

- **A vector is only comparable with vectors from the same model** (specs/020 B3.4).
  `explorer_rows.embedding_model` records which model made each one; `db:label` re-embeds a row
  it labels when the model changed, and `db:label:embed` rewrites the rest (raw SQL, labels kept).
  The review queue orders by one model's vectors only. Thresholds tuned on one model's cosines
  (`resolve.service.ts` `MIN_SCORE` 0.3, `STRONG` 0.38) do not carry to another, which is why the
  swap rule compares embedders by threshold-free recall@8 first.

- **An inference backend that cannot serve a capability fails at boot, not in a request.**
  `backendFor` refuses `decide` on `openai`, `complete` on the CPU sidecar, and `stride` without
  `EXPLORER_STRIDE_OPT_IN=1` and a key (the LGU's opt-in is the data agreement, decision 4). A
  global `EXPLORER_INFERENCE=sidecar` leaves chat on `openai` on purpose.

- **The workbook check is one file in two places.** `api/src/explorer/workbook/workbook.ts` is the source; `client/src/lib/explore/workbook.ts` is a copy (`cp` it over), and `workbook.test.ts` fails when they differ. It imports nothing for that reason.

## Client UI

- **Never hand-roll a page scroll lock next to a Base UI modal.** Base UI Dialog/Sheet (and Menu/Select, modal by default) lock `<html>`/`<body>` scroll through one ref-counted locker that locks and unlocks in a `setTimeout(0)`. The program drawer and the add-project sheet *also* snapshotted `overflow` and wrote the snapshot back; a snapshot taken while Base UI held its lock was `"hidden"`, restored after Base UI let go, and because the root layout survives navigation every page after it stopped scrolling until a reload (2026-10-19, dashboard and demo). Let the modal lock; `section-outline.tsx` (not a Base UI modal) clears rather than restores. `client/src/lib/source-guards.test.ts` fails on a new one.

- **State that must outlive a URL change belongs in a layout, not a page.** The registry pushes `/aip-registry/<year>/program/<id>` with `history.pushState` as drawers open. As a page under `[[...ppa]]` it remounted — open drawer, filters and list gone — whenever a server action's `revalidatePath` refetched the tree, because the refetch is for the *pushed* URL and the page segment's params had changed. It now lives in `app/aip-registry/[year]/layout.tsx`; the catch-all page renders nothing. The same layout tracks the path from `popstate` and its own writes rather than trusting `usePathname` after a revalidation.

- **A route handler must not build a redirect from `request.url`.** In the standalone container (`HOSTNAME=0.0.0.0`) a route handler's `request.url` is the bind address, so `NextResponse.redirect(new URL(path, request.url))` sent demo visitors to `https://0.0.0.0:3000/…` ("See it live", the expired-demo restart). Return `new NextResponse(null, { status: 307, headers: { Location: path } })` — a relative Location the browser resolves against the real host. Middleware is unaffected. Same guard test.

- **Switching language is a full page load, never a `next/link`.** `/fil/x` and `/bcl/x` are middleware rewrites of `/x` (specs/014), so to the client router the three are one route: a soft navigation between them changed the URL and kept the page, and `<html lang>` lives in the root layout, which a soft navigation never re-renders. The language switcher uses plain anchors (`source-guards.test.ts` fails on `next/link` there). Links *within* a language (`LocaleLink`) are fine. **`next.config.ts` redirects match before the middleware strips the prefix**, so a redirect for `/x` needs a `/:locale(fil|bcl)/x` twin or the prefixed URL 404s.

## Infrastructure

- **`.dockerignore` drops every `*.md`, so a Markdown file the API reads at runtime must be let back in.** The explorer's model prompt (`api/src/explorer/prompts/ask.v1.md`) is copied to `dist/` by `nest-cli.json` — locally. In the image it never existed, and every Ask that missed a card answered `500 Prompt ask.v1.md not found` on dev from the day Ask shipped; unit tests and local runs all passed. `!api/src/explorer/prompts/*.md` lets it back in. Check a runtime-read file with a throwaway build: `printf 'FROM busybox\nCOPY <path> /p\nRUN ls /p\n' | docker build -f- .`.

- **nginx owns `/api/v1/*` only; the client owns the rest of `/api/*`.** In production one origin is split across two containers by path (`nginx/nginx.conf`), and the Next client serves its own same-origin route handlers under `client/src/app/api/` — the program fetch behind `/programs/[id]/edit`, the `/api/events` SSE proxy, the xlsx exports. Widening the block to `location /api/` hands all of them to NestJS, which has no such routes and answers `{"message":"Cannot GET …","error":"Not Found"}` — and the edit page renders `body.error`, so the symptom is a bare **"Not Found"** page, not a 404. It is invisible on localhost (no proxy) and on Azure dev/staging (client and API are separate FQDNs), so **prod is the only place this shows**; it shipped with the DO stack and broke five features for the life of that host. `client/src/lib/nginx-routes.test.ts` fails if the prefixes ever overlap again. **Deploying an nginx.conf change takes a container recreate, not a reload.** The DO pipeline does ship the file (`git archive` → scp → `tar xzf` into `/opt/naga-budget`), but `docker compose up -d` hashes a service's config — image, env, volume declarations — never the contents of a bind-mounted file, and `tar` *replaces* the file rather than truncating it, so the container stays bound to the old inode and even `nginx -s reload` re-reads the old config. `docker compose up -d --force-recreate nginx` is what rebinds the mount; the pipeline now runs it. Verify with `docker compose exec -T nginx grep 'location /api' /etc/nginx/conf.d/default.conf`, never by reading the host file.

- **A new third-party host must be added to the CSP in `client/next.config.ts`, or it fails silently.** Every page carries a Content-Security-Policy that allows only `'self'`, GA4 and reCAPTCHA. A script, iframe, image or fetch to any other origin (a map tile server, an embedded video, a font CDN, a storage bucket shown as an `<img>`) is blocked in the browser with only a console message, and nothing fails on the server or in CI. GA4's hosts were not complete in Google's own guide (it also beacons to `www.google.com/g/collect`), so check a new host in a real browser with the console open, not from the docs. The API sets its own headers in `api/src/main.ts`; nginx sets none, so nothing is sent twice.

## Projects (PPMP)

- **A "PPMP" is product-named "Project" everywhere in the UI, and it is deliberately not part of the AIP workflow.** `PPMP` (`api/src/ppmp/`) has a **small approval gate of its own**, `PpmpStatus` `DRAFT` / `APPROVED` / `REVISION`: `POST /ppmp/:id/approve` (`aip:publish`) is a precondition for publishing; any content edit on an `APPROVED` Project reverts it — to `DRAFT` if never published, to `REVISION` *and unpublished* if it was live. There is no snapshot layer: the edit is saved immediately. **The Program link is free text**, `PPMP.fundingProgram` — the required `@unique` FK to `Program` from specs/005 was removed (`20260818010000_ppmp_unlink_program_add_feedback_fields`) because forcing a Project through an existing Program row didn't match how offices plan. `aipCycleId` only tags the fiscal year. Expense class and UACS object are **not** cross-validated on PPMP line items (AIP `LineItem` does enforce it). `PpmpComment`/`PpmpFeedback` are small Project-scoped models, not extensions of `ProgramComment`; History is synthesised from existing timestamps (`ppmp-history.util.ts`), there is no audit table. The authenticated list is `/ppmp-registry`; `/ppmp` is the public page. A Project is **Indicative** or **Final** (specs/012 P5): the Final copy is made from the Indicative one only after the year's Ordinance is enacted, and each line may link to **one** budget row (AIP program/PA while Indicative, Ordinance PPA once Final) — optional, beside the free text, never the old required FK. Those links are ON DELETE SET NULL, so any delete-and-rebuild of PAs must put them back (`restoreFromSnapshot` does). Don't "fix" any of this toward the AIP state machine — see `docs/modules/ppmp.md` and `specs/001`–`005`.
