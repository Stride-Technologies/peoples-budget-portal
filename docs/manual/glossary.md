# Glossary

Plain-language definitions of the terms used across the portal and this manual.
For the technical/domain reference, see
[`api/docs/aip-reference.md`](../../api/docs/aip-reference.md).

| Term | Meaning |
|---|---|
| **AIP** | Annual Investment Program — the city's prioritised list of programs, projects, and activities to fund for a fiscal year. |
| **AIP cycle** | One fiscal year of AIP activity in the portal. Moves through Planning → Open → Closed → Locked. |
| **Program** | The top-level submission — one strategic initiative. Contains projects and activities. |
| **Project / Activity** | A concrete piece of work under a program. Holds the line items. |
| **Line item** | A single budgeted cost: quantity × unit cost. Classified PS, MOOE, FE or CO. |
| **PS / MOOE / FE / CO** | The four expense classes — **P**ersonnel **S**ervices; **M**aintenance & **O**ther **O**perating **E**xpenses; **F**inancial **E**xpenses (bank charges, interest, other financial charges); **C**apital **O**utlay. |
| **Fund source** | Where an entry's money comes from: the General Fund, or a fund set aside for a purpose (the school fund, the health fund, national government money, and so on). |
| **Special fund** | Money set aside by law for one purpose: the **SPA** (Special Purpose Appropriation), the **LDF** (20% Local Development Fund, at least 20% of the National Tax Allotment) and the **LDRRMF** (5% Local Disaster Risk Reduction and Management Fund). A special fund is a fund source, not an office: each entry paid from one sits under the office that runs it. |
| **LBP forms** | The Local Budget Preparation forms of the DBM budget manual, prepared before the budget hearings. The portal exports Form 4 (each office's mandate, outputs, indicators and targets) and Form 7 (the city's allocation by sector). |
| **Proponent** | The office or organisation that proposed a submission. |
| **LGU** | Local Government Unit — a city government office (one proponent track). |
| **NCPC** | The people's council: the umbrella for civil-society organisations. The abbreviation comes from the Naga City People's Council, where the portal was first used; your LGU's council works under its own name. |
| **CSO** | Civil-Society Organisation — a non-government organisation proposing through the NCPC. |
| **LFC** | Local Finance Committee — a group of city offices (CPDO, CBO, CTO, CMO) that is the AIP's final approving body. The offices approve **in sequence** (a set order), one at a time; the program is approved only when all of them have approved, and any office can return it for revision. |
| **Committee approval** | The approval gate, entered directly from Head Reviewed. The LFC offices approve in turn; every office must approve for the program to reach Approved. Any office's return sends the program back for revision and stops the sequence. |
| **For Revision** | Workflow stage — the program was submitted and then returned for changes by an LFC committee return. Editable and resubmittable just like Draft, but named distinctly so it's clear the program was returned. |
| **Finish Line** | One of the LGU's top-level goals (the site shows them under the name your LGU set, "Development Priorities" by default). Every program is tagged to one. Each carries a yearly budget ceiling. |
| **Cluster** | A strategic grouping of offices and organisations. Determines which peers can see and comment on each other's submissions. |
| **PAP Sector** | The DBM 4-digit classification of public expenditure. Distinct from a cluster. |
| **UACS** | Unified Accounts Code Structure — the DBM's standard chart of accounts. Each line item picks a UACS object code. |
| **SGLG** | Seal of Good Local Governance — a DILG recognition program. A program can optionally be tagged to an SGLG indicator. |
| **SDG** | Sustainable Development Goals — the 17 global goals of the UN's 2030 Agenda. A program can be tagged to as many of them as it supports. They appear on the AIP form's extended sheet. |
| **CCET / Climate tag** | Climate Change Expenditure Tagging — marking how much of a project/activity's budget supports climate adaptation or mitigation. |
| **MFO / Expected output** | Major Final Output — the deliverable a program or project/activity produces. |
| **Budget ceiling** | The maximum budget for a finish line in a cycle, split between an LGU portion and a CSO portion. |
| **AIP reference code** | The structured code identifying a submission. The **tentative** code appears at creation and is rebuilt whenever the data behind it changes — the implementing office, the PAP sector, or the item's position in the list. Deleting an item closes the gap it leaves. The **final** code is assigned at approval and never changes. |
| **Draft** | Workflow stage — the proponent is still preparing a brand-new submission. Once submitted and later returned, the program lands in **For Revision** instead. |
| **Submitted** | Workflow stage — sent in, awaiting the proponent's own Head review. |
| **Head Reviewed** | Workflow stage — the proponent's Head signed off; ready for the Head to submit to the LFC committee for approval. |
| **Endorsed** *(retired)* | A legacy workflow stage from when endorsement gated approval. Endorsement is now advisory and non-gating, so programs no longer enter this state; it remains only for historical/in-flight records. |
| **Approved** | Workflow stage — accepted into the AIP, with a permanent reference code. |
| **Rejected** | Workflow stage — declined; stays visible but never receives a final code. |
| **Head review** | The step where a proponent office's own Head forwards a submitted program. |
| **Endorsement** | An advisory, affirmative concurrence by an endorser — the Head of an endorsing city office, the NCPC head, or an endorsing CSO's representative. Optional and non-gating — it never changes a submission's status and is never required to advance. Each endorser's concurrence is recorded and shown separately. Concerns are raised as comments, not a rejection. |
| **Verdict** | The record written when a program is finalized to Approved by the LFC committee (who approved, when). The Administrator no longer issues verdicts — the LFC committee is the sole approval authority. |
| **Comment thread** | A discussion on a submission. Threads must be resolved before a program can be (re)submitted. |
| **Version** | An immutable snapshot of a submission taken each time it is submitted. Used for side-by-side comparison. |
| **Activity stream** | The timeline of comments, endorsements, and verdicts on a submission. |
| **Role** | Staff, Head, or Super Admin (Administrator) — determines what you can do. |
| **Unread dot** | The blue marker on a registry row indicating activity you haven't seen yet. |
